# 实施计划 — Space Cadet 复刻 MVP

架构决策见 `docs/adr/`，领域术语见 `CONTEXT.md`。本文只讲做什么、按什么顺序做、怎么验证。

## 一、MVP 目标

在微信小游戏上跑通一个**手感成立**的单层**台面**。判定标准只有一条：球在**挡板**上被拍出去时，玩家觉得「这一下是我控制得准」，而不是随机的。

## 二、范围内

| 模块 | 内容 |
|---|---|
| 载体与工程 | 小游戏项目骨架、TypeScript + esbuild 单文件产物、three.js r117 + 自写 adapter |
| 相机 | 竖屏、固定斜俯视、只改距离不改角度 |
| 台面几何 | 外轮廓墙、内侧导轨、发射航道、左右返回航道入口、**反弹器**；声明式数据 → 几何 + 碰撞体 + 贴图 |
| **球** | 单球，半径与质量可调；固定步长 + 子步进 |
| **挡板** | 左右各一，角冲量拍击，按下/松开的响应时间可调 |
| **发射器** | 长按蓄力、松手击发，蓄力值映射到初速 |
| **缓冲器** | 3 个攻击缓冲器：得分 + 击退冲量 + 连击计数 |
| **击倒目标** | 3 个：击中得分、短暂倒下后复位 |
| **点亮目标** | 3 个**使命目标**：仅点亮、不计分 |
| 计分 | 分数、剩余球数、本地最高分 |
| **坠毁** | 底部中央直漏 + 左右外侧航道 |
| **倾斜** | 连续快速摇晃触发，本球立即结束 |
| HUD | 自绘：分数 / 球数 / 当前状态（就绪、发射中、倾斜） |
| 音效 | WebAudio 程序化合成：撞墙、缓冲器、挡板、发射、坠毁 |

## 三、范围外（明确排期到后续）

- **台面层**与坡道类组件：发射坡道、超空间、虫洞、黑洞
- 危险材料目标组、奖章目标、**扩大战场**、旗帜、引力井、中央立柱、加分航道、返回航道计分
- **使命**系统与**军衔**系统（进度灯、名次灯）
- **技能发射**判定
- **重玩球**与**加分球**
- 云排行榜、分享、好友对战
- 多球（multiball）

> 使命目标在 MVP 中只负责亮灯与音效反馈，不驱动任何流程——这是刻意留的接口，不是漏做。

## 五、M1 实际发现（实测，非推测）

M1 的价值超出了「搭骨架」——它把三条架构断言变成了可执行的检查，并暴露出三个真实缺陷。

**被验证的断言**

- 相机俯角在 16:9 / 19.5:9 / 21:9 / 4:3 / 3:4 / 9:19.5 六种比例下恒为 **62.00°**，只有距离变化（231.3 → 313.0）。ADR-0006 的「只改距离不改角度」成立。
- 台面在全部比例下 NDC 最大 **0.960**（恰为 1 − 4% 边距），不被裁切。
- 主循环 300 帧（4983ms）执行 **598** 次逻辑步，与 120Hz 定步长理论值完全一致；单帧 5000ms 的巨大 delta 只补算 **8** 步、丢弃 22 步，死亡螺旋防护有效。

**被修正的缺陷**

1. **屏幕画布未挂到全局** —— 业务代码会取到离屏画布，表现为「渲染成功但屏幕全黑」。
2. **台面几何走的是遗留 `Geometry`** —— three@0.117.0 里短名几何类还不是 BufferGeometry，手工写 UV 时 `geometry.attributes` 为 `undefined`，直接抛异常。已全部改为 `*BufferGeometry` 变体（见 ADR-0004）。
3. **相机适配的解析近似不成立** —— 「长度 × sin(俯角)」低估竖直投影量，NDC 冲到 1.191，近端被裁掉约 19%。已改为对真实投影做二分（见 ADR-0006）。

**新增的验证手段**

`npm run smoke` 在 Node 里用替身环境跑真实模块，覆盖 polyfill 加载、台面几何管线、相机适配、主循环定步长与卡顿防护。它不能替代真机验证，但把「改代码后有没有把别的弄坏」变成了秒级反馈。

## 六、M2 实际发现（实测，非推测）

M2 交付了 `src/physics/`（五个模块，零依赖）与 `demo/index.html`（单文件物理调试图）。ADR-0003 在决定自研物理时点名承认了三个弱区，M2 把它逐条变成了断言；过程里还揪出一个与物理无关、但只会在真机上发作的 polyfill 缺陷。

**被验证的断言**（`npm run smoke` 的 F 组）

| 断言 | 实测 |
|---|---|
| 几何与碰撞同源（ADR-0002） | 8 条围边，几何侧网格 name 集合与物理侧碰撞体 id 集合完全相等 |
| 求解器不吞/注能量（ADR-0003 弱区二） | 无损参数下 5 秒 9 次反弹，速率漂移 **0.0000%** |
| 满速不穿透（ADR-0003 弱区一） | 单步位移 5.83 / 球半径 2.3，子步最多 8，28 次反弹全程未穿出 |
| 低速接触不抖动 | 默认参数撞墙后横向速度 **0.000**（贴住）；阈值设 0 后 **−3.000**（原速弹回） |
| 挡板把手感做出来（ADR-0003 弱区三） | 拍击后向上峰值 **323.8**；对照组（不拍）**0.00** |

最后一条是关键：球受到的冲量取决于**相对运动挡板的相对速度**，而不是绝对速度。对照组 0.00 证明这条实现对了——如果误用绝对速度，不拍挡板也会把球弹飞。

**被修正的缺陷**

1. **polyfill 用低精度假时钟覆盖了真实 `performance`**（最严重）。原先判断条件是 `if (!g.performance)`，`g` 取 `GameGlobal`；真机上若 `GameGlobal` 是独立对象、内置全局只挂在 `globalThis` 上，条件恒为真，于是 `performance` 被换成 `Date.now()` 实现。症状不是崩溃，而是主循环拿到毫秒级抖动的时间戳，真机上表现为**周期性卡顿**。发现方式：把测试替身改成忠实的（`GameGlobal` 与 `globalThis` 是两个不同对象）之后，主循环步数开始随机抖动（586~590，期望 598）；修复后稳定 598。详见 ADR-0007。
2. **围边的坠毁开口被解释了两遍**。几何构建里手写了一遍「跳过下标 4」，`wallSegments()` 又把它当墙。同一份数据两个解释，正是 ADR-0002 要消灭的东西。已收敛为 `wallSpecs()` 单出口，几何与物理共享同一份带 id 的结果，并且**连发射航道隔墙也不再特殊处理**——它也是一条 `from → to` 线段。
3. **挡板角速度取的是「设定值」而不是「实际转过量」**。挡板到达行程终点会停下，若仍按设定速度算表面速度，球会在挡板已静止后被凭空推一把。改为返回实际转过的角度再除以 dt。

**新增的验证手段**

- `npm run demo` → `demo/index.html`：把同一份 `src/physics` 代码单独打包成自包含 HTML。物理不依赖 three 与小游戏 API 的约束在这里兑现成收益——调手感不用等小游戏构建，也不用真机预览。
- `npm run demo-check`：对调试图做**无头验证**。构建期校验 13 个元素 id 存在，之后用 DOM 替身把它真跑起来，断言加载不崩、渲染循环在跑、半屏映射按**逻辑平面坐标**而不是画布中线划分左右、方向键与重置可用、改参数会重建世界。这些是 DOM 装配错误，构建期查不出来。
- `npm run trace`：跑一遍完整台面，输出球的位置/速率/子步数与各类碰撞体命中次数。回答两个冒烟测试回答不了的问题：球会不会被卡住、能不能自然地从坠毁开口出局。当前基线：8 秒内走遍全台、命中 7 类碰撞体、9.5 秒从坠毁口出局。
- `npm run probe`：主循环每帧步数分布。就是它把上面第 1 条缺陷定位出来的。

## 七、风险与前置条件

| 风险 | 应对 |
|---|---|
| 真机 WebGL 1 渲染异常（**仍未验证**） | M1 的收尾动作。失败即重启选型，不往下投入 |
| 真机 `GameGlobal` 与 `globalThis` 的真实关系未知 | 已按「两个目标都写、两边都查」处理，任一种关系下都正确（ADR-0007）。真机验证时顺带确认一次 |
| 自研物理手感调校周期不可预测 | M2 已交付纯调试图，手感验证前移到渲染之前，不依赖美术 |
| 相机角度与台面几何一次性绑定 | M3 前先出静态构图确认图，确认后再校准几何 |
| 包体超限 | 当前压缩后 609 KB（主包 4096 KB），余量充足；一旦引入音频素材需重新核算 |
| three r117 双命名遗留 | M8 或升级 three 时统一清理 `*BufferGeometry` 后缀 |
| 审核资质 | 需游戏软著 + 工信部备案 + 防沉迷与适龄提示；个人主体仅限休闲等类目且不支持虚拟支付 |
