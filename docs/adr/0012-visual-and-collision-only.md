# 新增台面元素只做视觉与碰撞，不写各自的行为

Status: accepted

按原版重建台面会引入一大批此前没有的元素类型：坡道、虫洞、超空间发射口、燃料条、各类目标组。这些在原版里几乎都是有主动行为的机构——缓冲器发力、击倒目标倒下复位、虫洞吞球再弹出、弹射器把球踢走、中央挡柱升降、单向门只许单方向通过。

本次只做**视觉与碰撞**：元素有几何、有碰撞体、球撞得到，但不实现各自的专属行为。

为什么这样切：

- **架构上「纯装饰」反而更贵。** 台面元素数据是几何与碰撞的同一个来源（ADR-0002），`wallSpecs()` 这类出口一次产出两者。要把某个元素标成「不参与碰撞」，得给数据模型加一层只有装饰品会用到的开关。让它有碰撞体反而零额外成本，而且立刻可验证——`npm run trace` 能看出球在台面上撞到了什么。
- **行为可以逐个加，且不影响结构。** 挂在元素 id 上的行为是增量的：先有位置与碰撞，再加一条「球进入此区域则触发 X」。反过来先做行为，会让元素的位置与触发范围相互纠缠，改一处要重测另一处。
- **先看到完整台面，才知道哪些元素值得做深。** 原版有 22 个目标资源、20 多个灯组，逐个复刻行为是不可行的工作量。结构铺完之后，哪些元素值得投入行为（哪些玩家频繁接触、哪些只是背景装饰）才会有依据。

## Consequences

- 台面上会出现「能撞但不响应」的元素。这是**已知且刻意**的状态，不是缺陷。灯是例外（见 ADR-0013）——灯没有碰撞，它是纯视觉。
- 元素数据必须挂得住未来的行为：每个元素有稳定 id（沿用 `wallSpecs()` 的做法），行为按 id 索引，而不是按数组下标。
- 原版里纯逻辑的触发体（`TTripwire` 触发线、`TGate` 门）本次**不做**：它们没有体积、没有碰撞，只有行为，而行为不在本次范围内，做了也只是一堆看不见的空白。
- `npm run trace` 的基线要跟着更新。新增元素后球在台面上的碰撞次数与出局时间都会变，旧的「9.5 秒从坠毁口出局」会失效，M3 需要重建基线并记进 `plan.md`。
- 缓冲器、击倒目标、点亮目标这些**既有组件**的行为按 M5 原计划实现（缓冲器发力已有；击倒目标倒下复位、点亮目标亮灯待做）。本条约束的是**本次新增的结构元素**——坡道、虫洞、超空间发射口、引力井、中央立柱之类，它们只做结构与碰撞。两者不要混为一谈：前者是玩法的基础件，后者是场景的构成件。
