# 物理自研，不引入通用刚体引擎

Status: accepted

不用 cannon-es / rapier / ammo.js 之类的通用刚体引擎，自研平面碰撞求解。弹珠台恰好落在通用引擎的三个弱区：

1. **高速穿透**——球速足够高时一帧跨过薄壁，通用引擎需要 CCD，而开源 JS 引擎的 CCD 实现普遍不完整或默认关闭。
2. **能量守恒**——弯道里球需要连续滚动几十圈而不明显衰减，迭代式接触求解器会持续抹掉速度，球会「莫名变慢」。
3. **挡板手感**——挡板要的是可控的爆发冲量，不是物理正确的弹性碰撞；用运动学刚体驱动挡板会让击打力度受求解器迭代次数支配。

这三点在通用引擎里都要靠额外补丁绕开，补丁总量不比自研少，而且从此被引擎求解器的行为绑住，调手感时改不动底层。

自研范围很小：碰撞体只有圆（球、缓冲器、挡球柱）、线段（墙、导轨）、旋转线段（挡板）三类；响应用冲量法加可调的恢复系数与摩擦；所有手感参数集中在一处便于调校。

## Consequences

- 「固定步长 + 子步进」必须自己保证，物理不能跟着渲染帧率走。
- 倾斜判定、单向门、滚动触发区等原版特性要自己写——但它们本来就是台面逻辑，不属于物理引擎职责范围。
- 需要一个不依赖渲染的可视化调试图，否则手感参数会退化成盲调。
