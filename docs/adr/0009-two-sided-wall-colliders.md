# 线段碰撞体是双面的

Status: accepted

围边（线段碰撞体）两面都是实体：碰撞法线不固定，按「球心落在线段的哪一侧」现算。

单面法线在这里是行不通的，原因在发射航道。航道与主台面之间只有一条**零厚度**的隔墙（`wall:lane-inner`，逻辑平面上是 x = 39 的一条竖线），而球在这条线的左右两侧都可能存在——航道里有一条，台面上有一条。如果把法线按「朝向台面内侧」定死，球在航道那一侧碰撞时会被推向错误方向，直接穿墙，而且症状是「球偶尔从航道里跑到台面外」，极难复现和定位。

代价很小：理论上如果球跑到了台面之外，双面碰撞体会把它继续往外推。但球出不去——围边把台面封成一个闭合区域，唯一的开口（坠毁口）外侧是 `outOfBounds` 判定，不依赖碰撞。所以这个代价碰不到。

数据侧配套一条约束：每条围边的「参考法线」（用于球心恰好落在线段上、分离方向无从计算时的兜底）由 `makeSegment` 的 `inwardFrom` 参数决定，调用方传台面中心。这让**外轮廓的点序不再影响碰撞正确性**——顺时针还是逆时针排列都对。

## Consequences

- M3 对着原版截图校准台面轮廓时可以自由增删、重排轮廓点，不必担心把某条墙的朝向弄反。这是选这个方案最实在的收益。
- 几何侧因此收敛到与物理同一个数据出口 `wallSpecs()`：它一次性给出「哪条边立墙」以及每条墙的稳定 id。几何构建连发射航道隔墙都不再特殊处理——隔墙也是一条 `from → to` 的线段，按同样的方式算长度与倾角即可，少一处特殊分支就少一处走形。
- 冒烟测试用「几何侧围边网格的 name 集合」与「物理侧线段碰撞体的 id 集合」必须完全相等」来机器验证这条同源约束（ADR-0002 的落实）。当前共 8 条围边，两侧完全一致。
- 若将来出现**真正需要单面**的墙（比如只从一侧挡球、另一侧要能穿过的单向门），必须新增一种碰撞体类型而不是把线段改回单面——改回单面会立刻重新引入航道穿墙问题。
