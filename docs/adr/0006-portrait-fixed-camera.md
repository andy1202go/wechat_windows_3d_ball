# 竖屏，相机固定斜俯视

Status: accepted

游戏锁定竖屏，相机固定在一个斜俯视角度（俯角 62°，竖直 FOV 45°），玩家不能旋转或缩放。

原版桌面本身就是竖长条形（宽高比约 1:1.7），竖屏能让**台面**占满可用区域，且左右半屏触摸热区与拇指自然落点重合。相机固定是因为台面几何的浮雕高度、组件之间的遮挡关系都是针对这一个角度设计的，允许旋转会让这些设计在多数角度下失效。

## Consequences

- 相机参数一旦确定就等同于台面几何的一部分，调整视角等于重做台面。这是本决定难以逆转的原因。
- **适配必须对真实投影做数值求解，不能用解析近似。** 「台面长度 × sin(俯角)」这类公式会系统性低估竖直投影量——台面是一块有纵深的斜置平面，近端比远端离相机近得多。实测解析式给出距离 194 时 NDC 冲到 **1.191**（近端被裁掉约 19%），而二分求解真实投影后压到 **0.960**（正好是设定的 4% 边距）。因此 `fit()` 的入参是世界坐标点集而不是台面尺寸，实现是对投影做二分。这也让台面轮廓变化时适配自动仍然正确。
- 适配只改变相机与注视点的距离，**角度恒定**。冒烟测试覆盖 16:9 / 19.5:9 / 21:9 / 4:3 / 3:4 / 9:19.5 六种比例：俯角实测恒为 62.00°，距离在 231.3（宽比例，长度约束生效）到 313.0（窄比例，宽度约束生效）之间变化。
- 目标机型 9:19.5 下台面纵向只占 NDC 的 0.672，上下留出的空白正好分配给自绘 HUD 与发射条，与布局设计一致。
- 小游戏没有 WXML，计分板与 UI 只能压缩在顶部/底部窄条，或作为 3D 元素浮动在台面上方自绘。调试面板已用「贴在相机前方的平面 + CanvasTexture」验证了这条路径。
- 需在主流机型比例（16:9 至 21:9）下验证台面不被裁切；极宽或极窄比例用留白或微调距离适配，**不改变相机角度**。
