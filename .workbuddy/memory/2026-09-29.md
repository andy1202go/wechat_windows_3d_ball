### M1 实测发现（三个真 bug，均已修复）

1. **屏幕画布未挂到全局** —— 业务代码会取到离屏画布，表现为「渲染成功但屏幕全黑」。
2. **three@0.117.0 几何类双命名** —— 短名 `BoxGeometry`/`ExtrudeGeometry` 等在这版仍是遗留 `Geometry`（无 `.attributes`），手工写 UV 直接抛异常。已全部改用 `*BufferGeometry` 变体。我最初的判断是反的，靠探针实测纠正。
3. **相机适配的解析近似不成立** —— 「长度 × sin(俯角)」低估竖直投影量，NDC 冲到 1.191（近端被裁掉约 19%）。改为对真实投影二分，压到 0.960。

### 本轮最重要的自我纠错：polyfill 用假时钟覆盖了真实 performance

原先判断条件是 `if (!g.performance)`，`g` 取 `GameGlobal`。真机上若 `GameGlobal` 是独立对象、内置全局只挂在 `globalThis` 上，条件恒为真 → `performance` 被换成 `Date.now()` 实现 → 主循环拿到毫秒级抖动的时间戳 → **真机周期性卡顿，且完全无法归因到 polyfill**。

发现路径（关键，值得复用这个方法论）：
1. 先把测试替身改成忠实的：让 `GameGlobal` 与 `globalThis` 是两个不同对象（旧替身写成同一个，正好掩盖了这个 bug）
2. 冒烟测试立刻报警：主循环步数在 586~590 之间随机抖动（期望 598）
3. 写 `tools/probe-loop.ts` 打出每帧步数分布，发现「前 4~6 帧都是 0 步」→ 说明 `performance.now()` 不是受控时钟
4. 修复：所有全局写入双写两个目标；判断全局能力一律走 `readGlobal()` 两个目标都查
5. 修复后有无前置步骤结果完全一致，稳定 598 步

**结论：测试替身必须比真机更严格，不能更宽松。** 任何「为了通过测试而放松替身忠实度」的改动都要先自问：这条差异真机上真的不存在吗？

### 另外两个被修正的缺陷

1. **围边的坠毁开口被解释了两遍** — 几何里手写「跳过下标 4」，`wallSegments()` 又把它当墙。收敛为 `wallSpecs()` 单出口（带 id），几何与物理共享；连发射航道隔墙也不再有特殊分支（它也是一条 from→to 线段）。
2. **挡板角速度取「设定值」而非「实际转过量」** — 挡板到行程终点会停下，仍按设定速度算接触点表面速度的话，球会在挡板已静止后被凭空推一把。`advanceFlipper` 改为返回实际转过的角度。

### trace 基线（M3 校准台面时对照用）

球从 (0,150) 以 (30,−300) 出发，默认参数：8 秒内走遍全台，命中 7 类碰撞体（顶墙 4、航道隔墙 4、左挡板 4、缓冲器 2 三次、缓冲器 1 两次、反弹器 0 两次、右挡板 2 两次），9.5 秒从坠毁开口出局。

### 提交时踩到的环境坑

本机**全局 git 身份是空缺的** —— `~/.gitconfig` 只有 `credential.helper` 与 `http.sslcainfo`，
一提交就报：

```
fatal: 无法自动探测邮件地址（得到 'LiangBo@LiangBo-pc.(none)'）
```

按历史提交的作者补齐，**不要凭想象填**：

```bash
git log -1 --format='%an <%ae>'    # → Andy L <andy1202go@163.com>
git config --global user.name  "Andy L"
git config --global user.email "andy1202go@163.com"
```

author 仍是 `Andy L` —— 取值要看 `%an`，不是 `%cn`。

### 推送到远程 main

```bash
export HOME=/home/LiangBo
GIT_TERMINAL_PROMPT=0 git push origin HEAD:main   # → 42e1d7a..790dcec
```

远程 `refs/heads/main` 现为 `790dcec`（本地 `origin/main` 同步更新）。

三个值得记的点：

1. **用 `HEAD:main` 而不是先切分支再推。** 本地 `main` 被另一个 worktree 检出，
   `git checkout main` 会失败；指定 refspec 直接推送则完全不受影响。
2. **`GIT_TERMINAL_PROMPT=0`** —— 凭据失效时快速失败，不挂在交互式用户名/密码提示上。
3. **副作用：别的 worktree 的本地分支不会跟着走。** 另一个 worktree
   （`/data/usershare/Code/Github/wechat_windows_3d_ball`）的本地 `main` 仍停在 `42e1d7a`，
   需要在那里 `git pull`。推 refspec 更新的是远程，不是其他工作副本的本地引用。

4. 灯的做法 → **独立灯对象 + 分组控制**（不是 300 个 Mesh，合并绘制、按组批量更新）
5. 起步方式 → **先做浏览器 3D 预览**（美术反馈回路优先于台面数据改动）
